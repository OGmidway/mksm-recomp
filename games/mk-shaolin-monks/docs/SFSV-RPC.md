## Identification

SID `0x53465356` is the SFSV endpoint of the game's SNDF sound driver. RPC `0x8000` exchanges a queued sound command packet and callback notifications. It is not an archive read RPC.

Evidence from the user-supplied MKSM.rar PS2 decompilation:
- `FUN_00462740` binds SNDF `0x534E4446` and SFSV `0x53465356` together; the adjacent version string identifies SNDF Ver 2.24b, July 21 2005.
- `FUN_00463308` writes twenty-byte command records into a 128-entry EE queue.
- `FUN_00463BD8` packages those records and calls SifCallRpc with the exact addresses and sizes from the reported trace. The command count is at send+0xA00 (0x771400), NOT at the start of the packet. Zero first sixteen bytes alone cannot prove an empty packet.
- `FUN_00463880` is the completion callback. It releases the batch only when response word 0 is zero.

Verified against the actual extracted `IOP/sndfi.irx`, SHA256 `3bff7898bc43c5592a6cfeccbae77714d935de706a5b138b98cd5255aca1f968`: its registration materializes this SID around module offset 0xBAA4 and registers handler 0xC2C8. ## Wire layout

| Buffer | Offset | Meaning |
|---|---|---|
| send, 0xA40 bytes | 0..0x9FF | 128 records of 20 bytes: two 16-bit fields, four 32-bit fields |
| send | 0xA00 | 32-bit command count |
| receive, 0x1C0 bytes | 0 | 0 = accepted; 1 = busy, retain batch |
| receive | 4, 8 | notification value and presence flag for optional callback |
| receive | 0x10..0x3F | 48 per-slot notification bytes |
| receive | 0x40..0x1BF | 48 pairs of notification words |

## Implemented scope

`ps2xIOP/src/modules/mk_sfsv.cpp` implements the idle update and backpressure response, registered only for exact ELF/entry/CRC Shaolin Monks identity. It validates complete packets, counts, address overflow, and guest reads/writes; writes only the 448-byte response; preserves the EE completion callback; and signals NOWAIT completion. Unknown RPCs and malformed packets remain unhandled.

This is a partial sound transport implementation, not a sound engine. Empty batches return accepted with no notifications. Nonempty batches return the real busy status so the EE retains their commands. They are NOT falsely acknowledged as played. Metrics count idle and busy calls, and a bounded diagnostic captures the first queued batch.
